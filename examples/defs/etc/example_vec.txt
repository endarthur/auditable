# `@gcu/vec`

A pure-JS NumPy-equivalent for the regime where the wasm boundary cost dominates over the actual numerical work — typically arrays under ~50K elements and matrices ≤ 200×200.

`vec` is `Float64Array` and tight `for` loops, all the way down. V8's JIT inlines and autovectorizes them to near-C performance. No wasm, no scope discipline, no allocation contexts — JS GC handles lifetimes.

This notebook shows vec in both **JS cells** (direct API) and **adder cells** (Python with operator overloading via the bridge).

/// code collapsed

const vec = await load("./ext/vec/index.js")

## creation

Standard NumPy-flavored constructors. `from` auto-detects shape from nested arrays:

/// code
const a = vec.from([1, 2, 3, 4, 5])
const m = vec.from([[1, 2, 3], [4, 5, 6]])
const z = vec.zeros([3, 3])
const I = vec.eye(4)
const xs = vec.linspace(0, 1, 11)
const r = vec.range(10)

ui.display(`a       = ${a}`)
ui.display(`m       = ${m}`)
ui.display(`I shape = [${I.shape}]`)
ui.display(`xs      = ${xs}`)

/// md
## element-wise math with broadcasting

Three dispatch arms inside each binary op — scalar, shape-equal, and broadcast. The first two are tight flat loops V8 vectorizes; broadcast is stride-iterated:

/// code
const v = vec.from([1, 2, 3])
const M = vec.from([[10, 20, 30], [40, 50, 60]])

// Scalar broadcast.
const c1 = vec.add(v, 100)
ui.display(`v + 100 = ${c1}`)

// Row vector broadcast across rows of a matrix.
const c2 = vec.add(M, v)
ui.display(`M + v   = ${c2}`)

// Column vector tiled across columns.
const col = vec.from([100, 200], [2, 1])
const c3 = vec.add(M, col)
ui.display(`M + col = ${c3}`)

/// md
## reductions with axis

Without `axis`: scalar. With `{ axis: i }`: NdArray with that axis dropped.

/// code
const m2 = vec.from([[1, 2, 3], [4, 5, 6], [7, 8, 9]])

ui.display(`sum(all)        = ${vec.sum(m2)}`)
ui.display(`sum(axis=0)     = ${vec.sum(m2, { axis: 0 })}`)
ui.display(`sum(axis=1)     = ${vec.sum(m2, { axis: 1 })}`)
ui.display(`mean(axis=0)    = ${vec.mean(m2, { axis: 0 })}`)
ui.display(`std(axis=1)     = ${vec.std(m2, { axis: 1 })}`)

/// md
## linear regression via `lstsq`

Fit `y = m·x + b` to noisy points using normal equations + Cholesky. Build the design matrix `A = [[x_i, 1], ...]`, solve `A^T A β = A^T y`:

/// code
// Synthesize: y = 2x + 3 + noise.
const N = 50
const xs2 = vec.range(N)
const ysData = new Float64Array(N)
let seed = 1
for (let i = 0; i < N; i++) {
  seed = (seed * 16807) % 2147483647
  const noise = ((seed - 1) / 2147483646 - 0.5) * 0.5
  ysData[i] = 2 * i + 3 + noise
}
const ys = new vec.NdArray(ysData, [N])

// Design matrix.
const A = vec.zeros([N, 2])
for (let i = 0; i < N; i++) {
  A.set(i, 0, i)
  A.set(i, 1, 1)
}

const beta = vec.lstsq(A, ys)
ui.display(`fitted slope     = ${beta.data[0].toFixed(4)} (true: 2)`)
ui.display(`fitted intercept = ${beta.data[1].toFixed(4)} (true: 3)`)

/// md
## small linear system — kriging-style stencil

Solve a 5×5 system. LU + partial pivoting; numerically stable for well-conditioned matrices:

/// code
const K = vec.from([
  [4, 1, 0, 0, 1],
  [1, 4, 1, 0, 0],
  [0, 1, 4, 1, 0],
  [0, 0, 1, 4, 1],
  [1, 0, 0, 1, 4],
])
const rhs = vec.from([1, 0, 0, 0, 0])
const x = vec.solve(K, rhs)

// Verify K x ≈ rhs.
const Kx = vec.dot(K, x)
ui.display(`x       = ${x}`)
ui.display(`K · x   = ${Kx}`)

/// md
## stress-tensor eigendecomposition (`eigSym3`)

For a symmetric 3×3 matrix, vec uses the closed-form Smith/Cardano algorithm — no iterations, instant. Returns eigenvalues sorted descending and orthonormal eigenvectors as columns. Geologically relevant for principal stresses, structural fabric, moment-of-inertia tensors:

/// code
const sigma = vec.from([
  [10, 2, 0],
  [2, 8, 1],
  [0, 1, 6],
])

const { values, vectors } = vec.eigSym3(sigma)

ui.display(`σ₁ (max)   = ${values.data[0].toFixed(4)}`)
ui.display(`σ₂         = ${values.data[1].toFixed(4)}`)
ui.display(`σ₃ (min)   = ${values.data[2].toFixed(4)}`)
ui.display(`eigenvecs (columns) =\n${vectors}`)

// Verify: sigma · v_i = λ_i · v_i for each i.
for (let i = 0; i < 3; i++) {
  const v_i = vec.from([
    vectors.data[0 * 3 + i],
    vectors.data[1 * 3 + i],
    vectors.data[2 * 3 + i],
  ])
  const lhs = vec.dot(sigma, v_i)
  const rhs = vec.mul(v_i, values.data[i])
  const residual = vec.norm(vec.sub(lhs, rhs))
  ui.display(`||σ·v${i+1} − λ${i+1}·v${i+1}|| = ${residual.toExponential(2)}`)
}

/// md
## general N×N symmetric eigen via Jacobi

For larger symmetric matrices (no closed form), `eigSym` uses Jacobi rotations with sweeps. Quadratic convergence — ~5–10 sweeps for matrices up to ~100×100:

/// code
// Build a random 6×6 SPD matrix: A = M^T M.
const Mdata = new Float64Array(36)
let s = 7
for (let i = 0; i < 36; i++) {
  s = (s * 16807) % 2147483647
  Mdata[i] = (s - 1) / 2147483646 - 0.5
}
const Mrand = new vec.NdArray(Mdata, [6, 6])
const Asym = vec.matmul(vec.transpose(Mrand), Mrand)

const eig = vec.eigSym(Asym)
ui.display(`eigenvalues (descending): ${eig.values.data.map(v => v.toFixed(4)).join(', ')}`)

// Reconstruct A = V D V^T and check.
const D6 = vec.zeros([6, 6])
for (let i = 0; i < 6; i++) D6.set(i, i, eig.values.data[i])
const recon = vec.matmul(vec.matmul(eig.vectors, D6), vec.transpose(eig.vectors))
const err = vec.norm(vec.sub(Asym, recon))
ui.display(`||A − V D Vᵀ|| = ${err.toExponential(2)}`)

/// md
## adder bridge — same operations from Python

The bridge wraps each `NdArray` in a `VecArray` with Python dunder methods. Operators (`+`, `-`, `*`, `/`, `@`, `**`) work via `__add__`/`__radd__`/etc.; iteration yields scalars (1D) or rows (2D); slicing produces copies.

Convention: extension registers as its package name (`vec`); user aliases:

/// adder
import vec as np

a = np.array([1, 2, 3, 4, 5])
b = np.array([10, 20, 30, 40, 50])

# Element-wise arithmetic, scalar promotion.
c = a + b
d = 2 * a + 1
e = a ** 2

# Reductions.
total = c.sum()
mn = c.mean()

print(f"a       = {a}")
print(f"a + b   = {c}")
print(f"2a + 1  = {d}")
print(f"a ** 2  = {e}")
print(f"sum(a+b) = {total}, mean = {mn}")

## adder — linear algebra

Same `np.linalg` namespace as you'd use with NumPy, just backed by vec's pure-JS implementations:

/// adder
import vec as np

# Stress tensor — same example, idiomatic Python.
sigma = np.array([
    [10, 2, 0],
    [2, 8, 1],
    [0, 1, 6],
])

values, vectors = np.linalg.eigh3(sigma)

print(f"σ₁ = {values[0]:.4f}")
print(f"σ₂ = {values[1]:.4f}")
print(f"σ₃ = {values[2]:.4f}")

# Verify orthonormality: V Vᵀ = I.
VVt = vectors @ vectors.T
print(f"V Vᵀ ≈ I:")
print(VVt)

## adder — solve and lstsq

/// adder
import vec as np

# Solve a 3×3 system.
A = np.array([[4, 1, 2], [1, 5, 1], [2, 1, 3]])
b = np.array([1, 2, 3])
x = np.linalg.solve(A, b)
print(f"x = {x}")
# Verify via matrix-vector product. np.dot is overloaded by ndim:
#   2D × 1D → 1D (matrix-vector); 2D × 2D → matmul.
print(f"A·x = {np.dot(A, x)}  (should equal b = {b.tolist()})")

# Linear regression via lstsq — fit y = 1.5x + 0.5.
xs = [1, 2, 3, 4, 5, 6, 7, 8]
ys = [1.5 * x + 0.5 for x in xs]
A_lsq = np.array([[x, 1] for x in xs])
b_lsq = np.array(ys)
beta = np.linalg.lstsq(A_lsq, b_lsq)
print(f"slope = {beta[0]:.4f}  (true: 1.5)")
print(f"intercept = {beta[1]:.4f}  (true: 0.5)")

## when to use `vec` vs `natra`

Both ship with Auditable, both register adder bridges. Pick per-task:

| | `@gcu/vec` | `@gcu/natra` |
|---|---|---|
| Backing | `Float64Array` (pure JS) | wasm linear memory |
| Op cost (small) | very fast (V8 JIT) | wasm dispatch overhead |
| Op cost (large) | slower (no SIMD) | fast (vectorized C) |
| Linear algebra | small dense direct | alpack BLAS via @atra |
| dtype | f64 only | i8/u8/i16/u16/i32/u32/f32/f64 |
| When to reach for it | daily-driver work | hot kernels, big arrays |

Rule of thumb: `vec` for "I just want to add two arrays and sum them"; `natra` for "I'm doing real linear algebra on a 1M-cell block model."
